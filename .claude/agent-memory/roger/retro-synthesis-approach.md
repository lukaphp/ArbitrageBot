When asked to synthesize multiple team members' Glad/Sad/Bad (or Mad) retrospective reflections into one summary: do not repeat each person's points one by one — extract the shared substance across them (what converges, what's in tension). Then, for every conclusion drawn, attach either a concrete action or an honest mitigation (if not solvable now/at all), each traceable back to a specific statement someone made — never water down to generic language like "miglioreremo la comunicazione." Where relevant, name an accountable owner: PO, the orchestrator (Claude, since it handles git/workflow-level things no individual agent or I can execute), a specific specialist agent, or explicitly flag "requires a PO decision, not an execution" when it's a product/process choice rather than a task.

**Why**: explicit PO instruction for the team's first full retrospective (2026-08-12/2026-08-13), see [[first-team-retro-findings]]. Generic synthesis would defeat the purpose of collecting six honest, specific reflections.

**How to apply**: applies to any future retrospective synthesis task, and by extension to any other multi-source synthesis work (e.g. aggregate.json itself, if that role is reinstated — see [[role-erosion-aggregate-json]]) — prefer specific, attributable claims over smoothed-over generalities.
